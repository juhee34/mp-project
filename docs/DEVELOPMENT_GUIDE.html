앱 소개서

Tiny Runners는 여섯 명의 작은 친구 중 한 명을 골라 그 친구의 고향을 달리는 2D 픽셀 러너 앱이다. 화면을 눌러 장애물을 넘는 간단한 조작 위에, 서로 다른 성격과 생활 공간, 음악과 이야기를 더한다.
라일은 움직이는 고사리 길을 지도에 담고 싶어 하고, 피코는 친구들이 쉬어 갈 수 있는 물길을 만든다. 캐릭터마다 달리는 이유가 다르므로 선택은 외형 교체 이상의 의미를 갖는다. 플레이가 끝나면 오늘 함께한 거리와 작은 기억을 확인하고, 도감에서 친구의 이야기를 읽을 수 있다.
이 앱은 학교 과제로 Android Studio에서 구현·시연·제출하는 것을 목표로 한다. 핵심은 캐릭터 선택, 게임 입력과 충돌, 이미지 애니메이션, 음악 재생, 데이터 저장, 화면 이동을 하나의 경험으로 연결하는 것이다. 현재 이 문서는 제작 계획과 소개서이며 완성된 게임이나 생성된 6개 배경·6곡을 의미하지 않는다.

기획 의도

짧게 즐기는 러닝 게임에 캐릭터와 친해지는 이유를 더한다. 높은 점수를 얻는 재미와 별개로, 서로 다른 고향을 구경하고 친구의 사소한 버릇을 알아가는 재미를 만든다. 감정을 직접 평가하거나 치료 효과를 주장하지 않으며, 판타지의 생활 속에서 호기심·아쉬움·장난스러움·안도감을 표현한다.

우리가 집중할 차이

친구의 집으로 돌아오는 러너 — 달리기 종료 후 점수표만 보여주지 않고 짧은 귀가 장면을 보여준다. 오늘 만난 것 하나가 집 안에 남는다. MVP에서는 라일의 창가 화분과 지도부터 구현한다. 시각적으로 확인 가능한 변화

같은 사건의 서로 다른 기억 — 예를 들어 사라진 바람종 사건을 라일과 피코가 각자 다르게 기억한다. 누구의 설명이 정답인지 판정하지 않고 두 관점이 모여 새로운 장면이 열린다. 기본 기능 완성 후 추가할 교차 에피소드

이야기를 기억하는 음악 — 각자의 기본 테마는 선택 즉시 다르고, 특정 기억을 얻으면 작은 악기 선율이 추가된다. 단순 템포 변경을 6곡으로 세지 않는다. 기본 6곡 이후 확장

돌봄의 상호성 — 사용자만 캐릭터를 돌보는 것이 아니라, 실패 뒤 캐릭터가 먼저 간식을 내밀거나 앉을 자리를 마련한다. 사용자의 실제 감정을 추정하지 않는다. 짧은 연출과 대사로 구현

쉬어도 유지되는 관계 — 연속 출석, 접속 공백 페널티, 친밀도 감소를 넣지 않는다. 실력 차이 때문에 이야기가 막히지 않도록 편안한 산책 모드와 감상 경로를 제공한다. 처음부터 적용할 운영 원칙

첫 목표는 6명 모두 선택하고 달릴 수 있는 앱입니다. 6명 선택을 유지한 상태에서 그림·배경·음악·이야기를 2명씩 다듬습니다. 한 명만 선택 가능한 버전을 최종 목표나 첫 시연 목표로 바꾸지 않습니다.

이 분담은 모델의 절대적인 우열이 아니라, 이미지 제작 도구와 프로젝트 통합 도구를 활용하면서 두 사람 모두 구현 기여가 남도록 나눈 제안입니다. 일반 채팅에서 코드만 복사하는 방식과 프로젝트 파일을 직접 읽고 실행하는 Codex/Claude Code 사용은 구분해야 합니다.

코드가 충돌하지 않게 하는 규칙

  • 하나의 저장소를 공유하고 A와 B의 작업 브랜치를 나눈다. 서로의 변경을 검토한 뒤 통합한다.
  • A 소유: 소개·선택·도감 화면, content 데이터, 아트 원본, 기획 문서. B 소유: game·audio·storage·프로젝트 설정.
  • AndroidManifest, Gradle, 공통 모델 및 저장 인터페이스는 B가 통합 관리한다. A는 필요한 변경을 요청 목록으로 전달한다.
  • 6개 캐릭터 ID와 리소스 경로는 공동 데이터 계약에 고정한다. 바꿀 때는 양쪽 참조를 함께 점검한다.
  • 각 작업 후 PROJECT_STATE.md에 완료 기능·실제 테스트·남은 문제·다음 작업을 기록한다. AI 채팅끼리 자동으로 기억을 공유한다고 가정하지 않는다.
  • A가 먼저 캐릭터 자료를 만들고 B는 임시 소재로 게임을 만드는 작업은 병행할 수 있다. 같은 파일의 동시 수정은 피한다.

소재 전달 규격

소재는 characterId별 폴더에 이름을 통일해 전달합니다. 예: mint/portrait.png, mint/run.png, mint/background.png, mint/theme.ogg. 실제 프로젝트의 폴더와 형식은 B와 첫 단계에서 확정합니다. 스프라이트 셀 크기·발 기준선·프레임 순서·배경 기준선·음원 반복 지점을 함께 적습니다.

구현 가정

현재 과제 안내가 없으므로 Kotlin + XML 화면 + Custom View/Canvas 게임을 임시 기준으로 작성했습니다. 언어·UI 방식·WebView 허용·마감·제출 형식은 수업 안내를 확인한 뒤 바꿀 수 있습니다. 앱스토어 등록과 별도 웹사이트 제작은 이번 기본 범위에 포함하지 않습니다.

매번 사용하는 공통 지침
우리는 학교 과제로 Android Studio에서 실행·시연·제출할 2D 픽셀 러너 앱 Tiny Runners를 2명이 만들고 있다. 나는 [A: ChatGPT 담당 / B: Claude 담당]이다. 이번에 지정한 단계와 내 담당 파일만 작업하라.
최종 목표와 첫 시연의 캐릭터 선택 수는 모두 6명이다. 캐릭터 수를 임의로 줄이지 마라. 초기에는 6명 모두 임시 소재로 플레이할 수 있게 만들고, 배경·연출·음악·서사는 단계적으로 완성한다.
과제의 언어와 UI 방식은 아직 제공되지 않았다. 본 계획은 Kotlin + XML 화면 + Custom View/Canvas 게임 화면을 임시 기준으로 삼는다. 과제 안내가 제공되면 그것을 우선하라. 실제 프로젝트의 SDK·Gradle·플러그인 버전을 확인하고 서로 맞는 버전을 사용하라. 이 문서의 예정 기능을 구현 완료로 간주하지 마라.
A는 기획·캐릭터 콘텐츠·이미지 제작과 소개/선택/도감 화면을 맡는다. B는 프로젝트 설정·게임 로직·오디오·저장·통합을 맡는다. 공통 데이터 계약과 파일 소유권을 먼저 확인한다. 담당 밖 파일은 변경 필요성을 기록하고 상대 작업을 덮어쓰지 않는다.
6명은 mint, cheese, popo, lumi, nunu, piko이다. 각자 외형·고향·성격·이야기·테마 음악이 다르지만 속도·점프·기본 충돌 판정은 같다. 능력 차이 없이 좋아하는 친구를 고르게 한다.
귀엽고 따뜻한 판타지로 다양한 감정을 표현한다. 입시·취업·빚·질환 같은 현실 소재를 직접 넣지 않는다. 쓸모를 증명해야 사랑받는 결말, 과잉 비극, 매번 같은 위로 대사, 미접속 죄책감, 출석 실패 벌칙을 넣지 않는다.
기존 4종의 승인된 픽셀 디자인을 유지한다. 생성 이미지를 완벽한 스프라이트나 무한 반복 배경으로 가정하지 않는다. 실제 음원이 없으면 음악이 완성되었다고 말하지 않는다. 205편 연구는 원문·실질 줄거리 검토이며 모두 완독하거나 영화를 전편 시청한 것이 아니다.
