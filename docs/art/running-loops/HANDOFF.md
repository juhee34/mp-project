# 달리는 길 반복 배경

사용자 확정: **집은 출발 때 한 번, 이후에는 달리는 길만 반복.** 집으로 돌아오는 반복 구조는 폐기했다.

## 구성
- 6명 × 출발 intro PNG + 반복 loop PNG = 12장. app/src/main/assets/backgrounds/running/.
- 한 장 높이 280px, 공통 바닥 기준 y256. 배경 아래 24px만 기존 엔진 바닥 띠 높이에 맞춘다. 충돌선은 바꾸지 않는다.
- 원본의 큰 집은 intro에만 있다. loop에는 지도·책갈피·장갑·종이배 같은 생활 소품과 길만 들어간다. 치즈의 먼 지붕과 누누의 작은 원경 창문은 마을 풍경으로 남긴다.
- 기존 승인 원본은 docs/art/background-source/에 보존. 새 첨부 보정본 3장은 docs/art/running-loop-source/에 보존.

## 내보내기와 접합
이미지 도구 보정본에서 집으로 돌아오는 가장자리(집 벽·큰 뿌리)를 제외했다. 기술 내보내기에서 바닥을 정렬하고, 서로 겹치는 160px 구간에 색 차이가 작은 연결 경로를 선택해 6px 폭으로 경계를 완화했다. 원본 디자인 전체를 새로 생성하거나 좌우 거울 복제하지 않았다. 출발 구간 끝은 반복 구간의 바로 앞 픽셀 흐름에 연결하고, 반복 이미지를 회전 배치해 외부 타일 경계가 같은 원화의 연속 구간에 놓이게 했다.

재생성: Windows PowerShell에서 scripts/export-running-backgrounds.ps1 실행. 원본 변경 시 manifest의 치수·해시도 갱신해야 한다. node scripts/validate-content.cjs가 경로·크기·해시·6명 구성을 확인한다.

## 게임 코드
RunningBackgroundMotion.parts가 한 번의 출발과 반복 풍경을 따로 배치한다. distance=0은 집, 출발 영역을 지난 모든 거리에는 loop만 있다. pause 시 거리가 그대로면 배경도 그대로다. 새 판은 집에서 출발한다. StoryBackground는 두 PNG를 시작 시 디코딩하고 프레임마다 재로딩하지 않는다. 화면 좌표를 반올림해 타일 사이 빈 줄을 방지한다.

## 검수
- 12장 원화와 경계 비교판을 육안 확인. 반복 이미지에 큰 출발 집이 없는 것을 확인.
- 검수용 preview.html은 단독 실행 가능. 출발/길로 넘어가기/길 3바퀴 뒤 버튼 제공. 실제 게임 플레이 화면은 아니다.
- 코드 테스트는 처음 출발, 출발 경계, 반복 경계, 장거리에서 집 재등장 금지, 화면 폭에 따른 빈 구간, 일시정지와 재시작을 검사한다.
- Android 실제 기기 검수 결과와 빌드 결과는 최종 작업 기록을 따른다. 미실행 기기 검수를 완료로 간주하지 않는다.

## 2026-11-11 게시 검토와 B팀 검증 인계
- 원본 커밋은 c95614f2d42145ef493af6d2683de43dabcbd7ab. 게시 검토 시 origin/main은 기준 커밋 c8fcbb6f1b979e066850b6e9298f5ba24719549d와 같았다. 추가 병합 충돌 없이 배경 관련 28개 파일만 차이 났다. 복구 bundle verify도 통과했다.
- RunningBackgroundMotion의 출발 구간 이후 loop만 배치하는 분기와 거리 0 복귀, StoryBackground의 시작 시 비트맵 로드·필터 비활성·좌표 반올림을 코드로 확인했다. gallery.png의 6명 출발/반복 영역을 육안 검토했으며 큰 출발 집은 반복 영역에 없다. 이는 실제 Android 주행 검수가 아니다.
- 게시 검토에서 node scripts/validate-content.cjs와 git diff --check HEAD~1 HEAD는 통과했다. 원래 작업 폴더의 소개·음원·대사·웹사이트 및 기존 미추적 로그/개인 설정은 이번 게시에서 제외한다.
- 이전 사본의 assembleDebug/단위 테스트 77개/Lint 오류 0·경고 44는 기존 제작 기록이다. 이번 재실행은 PowerShell의 옵션 전달 오류로 Gradle 작업 실행 전에 실패했다. 이후 사용자 지시로 빌드·테스트·기기 실행은 B팀 담당으로 넘겼으며 재시도하지 않았다.
- ADB 조회 당시 연결 기기는 없었다. 에뮬레이터 실행·APK 설치·개인 데이터 초기화는 하지 않았다.
- B팀 인수: 최신 PR을 기준으로 assembleDebug, testDebugUnitTest, lintDebug를 실행한다. 별도 테스트 계정/기기에서 6명 모두 집에서 출발 → 길로 전환 → 길 3회 이상 반복(집 재등장 없음) → 일시정지/재개 → 재시작 시 집 복귀를 확인한다. 화면 비율별 경계 틈·바닥선·HUD/장애물 대비도 확인한다.
- 팀 작업 방식은 작업 브랜치 push 후 PR, 상대 검토 후 main 병합이다. 브랜치 게시나 정적 검사만으로 main 반영 또는 기기 검수 완료라고 표시하지 않는다.

### 게시 중 main 갱신 반영
- PR #3: https://github.com/juhee34/mp-project/pull/3 . 최초 게시 후 main에 bbe51a717bf27809f2afc8e50205fe0e3b416bd6(거리 코인/꾸미기 상점)이 추가돼 작업 브랜치에 병합했다. PROJECT_STATE와 DATA_CONTRACT는 자동 병합됐고 충돌은 없었다. 팀원의 상점·계정/진행 연결 코드를 그대로 보존했다.
