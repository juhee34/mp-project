## 현재 산출물
`review/background-preview.html`은 로컬에서 열고 승인 원본 3장을 각각 선택하는 검수 화면이다. 업로드나 네트워크 전송 없이 브라우저 안에서 이미지 일부를 그린다. 원본은 변경하지 않는다. 캐릭터는 저장소의 승인 idle_0를 포함한다. 실제 플레이나 완성된 레이어 스크롤이 아니다.

## 검수 방법
1. 세 쌍의 파일 선택 버튼에 해당 원본 PNG를 지정한다.
2. 캐릭터를 선택하고 위/아래 컷 범위를 확인한다. 크림색 구분선을 자동 탐색하지만 실패하면 상단·하단 슬라이더로 조정한다.
3. 재생·거리·속도를 조절해 생활 공간과 이야기 소품을 읽을 시간이 있는지 확인한다.
4. 발 위치와 배경 바닥이 맞는지 바닥 기준을 조정한다. 가이드 표시로 바닥과 화면 잘림을 확인한다.
5. 반복 모드를 켜서 오른쪽 끝→왼쪽 집의 연결을 확인한다. 원본 양끝은 검증된 타일이 아니므로 연결 점프가 예상된다. 기본은 끝에서 멈춘다.

## 이후 구현 기준
- 실제 PNG 확보 후 원본 해시·크롭 좌표·원본 바닥 기준을 기록한다. 자동 추측만으로 확정하지 않는다.
- 한 장 그림을 여러 속도로 겹쳐 그리는 것은 진짜 시차 배경이 아니다. 전경 뒤에 가려진 원경 복원이 필요하므로 별도 검토 없이 레이어 완료 처리하지 않는다.
- 원본 디자인 보존을 우선해 먼저 단일 배경 스크롤로 화면 비율·가독성을 확인한다. 원경/중경/전경/바닥 분리는 다음 제작 단계로 남긴다.
- 이야기 구간은 집→발견→친구의 흔적 순서로 진행한다. 짧은 반복으로 순서를 무너뜨리지 않는다. 반복 연결용 별도 구간이 필요하다.
- 배경 이동은 engine.distance 기준. 일시정지 시 정지, 재시작 시 출발점으로 복귀. 비트맵 캐시 사용, 매 프레임 디코딩 금지.
- 기존 날씨 효과와 HUD, 장애물 대비를 확인한다. 소품은 비충돌 장식이며 플레이어 물리나 장애물 판정을 바꾸지 않는다.
- 6명 각각 준비→달리기→상승/하강→실패→재시작을 기기에서 확인한다.

## 2026-11-10 원본 확보 및 검수 결과
사용자가 다운로드한 승인 원본 3장을 `background-source/`에 그대로 복사했다. 모두 2169×725 PNG이며 다운로드 파일과 SHA-256이 동일하다. 표시 영역과 바닥 기준은 `background-manifest.json`에 기록했다. 원본 픽셀은 수정하지 않았다.

- Chrome의 960×540 Canvas에서 6명 모두 시작/끝 장면의 캐릭터 가독성 및 발 기준을 육안 확인했다. 라일은 실제 재생으로 이동과 달리기 전환도 확인했다.
- 크림색 외곽/중앙 여백을 제외하는 source rect를 지정했다. 라일/치즈 두 그림의 높이는 서로 다르므로 반으로 자르면 안 된다.
- 전체 원본의 좌우 끝은 서로 이어지지 않는다. `loopReady=false`, `layered=false`다. 반복 확인 모드는 문제를 관찰하기 위한 기능이다.
- 배경마다 바닥 높이가 다르다. 이번 좌표는 미리보기 기준이며 Android의 고정 충돌 바닥과 직접 같지 않다. 기기에서 HUD/장애물과 함께 최종 정렬해야 한다.
- Node 합성 DOM 동작 검사와 콘텐츠 검증 통과. 브라우저에서 전체 프레임별 검사나 Android 기기 검수는 하지 않았다.

## 다음 적용 단계: B 인수 규칙
1. 원본 3장과 manifest를 사용해 캐릭터별 source rect를 읽는다. `rect`는 원본 픽셀의 `[x,y,width,height]`, `floorY`는 잘린 영역 상단 기준이다.
2. 재디자인/재생성/자동 색상 변경 없이 원본을 표시한다. 현재는 단일 파노라마이며 원근 레이어가 아니다.
3. `destY = engineFloorY - floorY * renderScale`로 발 기준을 맞춘다. source 하단의 흙/벽돌 두께가 화면 하단을 전부 덮지 않을 수 있으므로 실제 기기에서 확인하고 기존 바닥 렌더링과 통합한다. 배경 때문에 충돌선을 옮기지 않는다.
4. 최초 검증은 일회 스크롤로 한다. 거리로 offset을 계산하고 끝에서 clamp, 일시정지 시 정지, 재시작 시 0으로 복원한다. 무한 러너 최종판에는 별도 연결 구간 또는 승인된 반복 구간이 필요하다.
5. Bitmap은 캐시하고 매 프레임 디코딩하지 않는다. 여섯 캐릭터 준비/달리기/점프/실패/HUD 가독성은 실제 게임에서 후속 검수한다.
6. 이번 A 작업은 검수용 원본/좌표/미리보기 준비까지다. 게임 런타임과 assets.json planned/null은 수정하지 않았다.
