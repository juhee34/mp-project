## 205편 조사 원리 적용과 두 명씩 검토

`research/`의 205개 조사 기록 중 관련 원리를 고르고 기존 캐릭터의 생활·관계에서 사건을 새로 구성했다. 205편 원전 전체를 이번에 다시 읽었다거나 독창성을 법적으로 보증한다는 뜻은 아니다. 적용한 조사 ID와 원리, 피한 전개는 각 원고 말미에 기록했다.

1. 라일·치즈: 실수 뒤의 안전함과 조건 없는 방문. 두 편 모두 물건이 나오지만 ‘정답 지도를 완성해 칭찬받기’와 ‘쓸모 있는 선물로 사랑받기’로 끝내지 않는다.
2. 포포·루미: 집과 바깥을 동시에 좋아하는 마음, 말 없는 관객의 반응. 돌아갈 장소의 확장과 공연 방식의 변화로 결말을 구별한다.
3. 누누·피코: 기억되고 싶은 마음, 서로 다른 속도. 존재를 증명하는 유용함이나 활기를 포기하는 순종으로 해결하지 않는다.

공통으로 교훈을 설명하는 마지막 연설, 능력 획득으로 결점 제거, 불행·죽음에 기대는 감동, 선행 뒤 의무적인 보답을 피했다. 지도·조개함·책갈피·종이배 등은 기존 캐릭터 설정의 소품이다. 조사 작품의 사건·대사·상징 묶음을 옮기는 방식으로 사용하지 않았다. 각 편은 독립적으로 읽을 수 있다.

## 구현된 사용 흐름

- 소개·친구 선택·프로필에서 **이야기 도감** 진입. 여섯 명을 바꾸어 각자의 소개·1편·후속 2편을 확인한다.
- 소개는 처음부터 읽는다. 1편은 해당 캐릭터 누적 100m에 열리며, 잠겼어도 **거리와 관계없이 감상하기**를 선택할 수 있다. 이 기준은 이번 구현의 기본값이며 데이터에서 조정한다.
- 목록에 **아직 읽지 않은 이야기 / 읽은 이야기 / 아직 열리지 않은 이야기 / 다음 이야기·준비 중**을 구분한다. 읽은 편에는 **다시 읽기**, 중간 종료한 편에는 **이어서 읽기**를 제공한다.
- 긴 본문은 짧은 페이지와 화자별 대사로 나눴다. 첫 에피소드별 13~21페이지다. **나중에 읽기 / 바로 달리기**는 본문 아래 고정 영역에 있어 완독 없이 이동할 수 있다.
- 페이지를 넘기면 위치만 저장한다. 마지막 페이지의 **읽음으로 저장**을 눌러야 읽은 것으로 처리한다. 다시 읽어도 기존 읽음 표시는 유지한다.
- 읽음·열림·페이지는 현재 기기의 계정별 로컬 저장이다. 다른 기기로 동기화되지 않는다. 거리 조회가 실패해도 이미 열린 이야기와 수동 감상은 가능하다.
- 후속편은 제목과 준비 중 안내만 표시한다. 제작용 개요를 완성 본문처럼 보여주지 않는다.

## 파일과 수정 방법

- 원문: `docs/STORY_MANUSCRIPT_01.md`, `02.md`, `03.md`.
- 내보내기: `python scripts/build-story-content.py` → `app/src/main/assets/content/stories.json` 및 `characters.json`의 storyIds.
- 콘텐츠 계약: `docs/DATA_CONTRACT.md`.
- 앱: `stories/Story.kt`(모델·파서·상태), `StoryStore.kt`(기기 저장), `StoryActivity.kt`(도감·독서).
- 진입 버튼: `characters/CharacterScreens.kt`; 등록: AndroidManifest.xml; 라벨: res/values/story_strings.xml.
- 검사: `node scripts/validate-content.cjs`; `app/src/test/.../stories/StoryTest.kt`.

원고 수정 뒤 생성 스크립트를 다시 실행한다. JSON만 직접 고치면 원고와 불일치하거나 다음 생성 때 변경이 사라진다. 캐릭터 ID와 기존 intro ID는 보존했다. B의 게임 물리·충돌·음악·Firestore 진행 저장 형식은 수정하지 않았다.

## A팀 도감 검토·수정

- StoryActivity: 목록·본문 스크롤 위치를 화면 재생성 때 복원하고, 독서 종료 뒤 기존 목록 위치로 돌아간다. 거리 콜백이 초기 레이아웃보다 먼저 도착해도 복원 위치를 0으로 덮어쓰지 않도록 했다. 페이지 이동은 본문 상단부터 표시한다.
- StoryActivity: 저장된 화면은 같은 계정에서만 복원하고, 늦게 도착한 거리 콜백도 현재 계정과 세대를 확인한다. 공용 조회 호출에서 예외가 나면 도감의 조회 실패 안내로 전환하며 소개·수동 감상은 계속 제공한다.
- StoryStore: A 소유의 책갈피 저장 결과를 화면에 반환하고 저장 실패 때 페이지를 넘기지 않고 안내한다. 계정별 저장 파일 이름과 읽음·열림 계약은 그대로다.
- StoryStoreTest: 책갈피 재열기, 명시적 읽음 완료, 읽음 유지, 계정 저장 이름과 데이터 분리, 저장 실패 반환을 추가 검증한다. 메모리 저장소를 이용한 단위 테스트이며 실제 Firebase 로그인이나 디스크 오류 재현을 대신하지 않는다.
- 승인 원고 본문, 공용 AuthService·ProgressStore, 게임·충돌·물리·음악 코드와 클라우드 동기화는 변경하지 않았다. 공유 CharacterScreens.kt에서는 도감 import·진입 버튼만 게시한다. 별도 소개 화면 개편과 음악 작업은 제외한다.

## B팀 인수 작업 — 기기 검수 미완료

실제 계정·기존 기록을 지우거나 바꾸지 말고 테스트 계정과 별도 에뮬레이터 데이터를 사용한다.

1. 소개·선택·프로필의 도감 진입, 6명 전환·각 4카드, 미독/읽음/잠김/준비 중 구분을 확인한다. outline 본문·감상 버튼이 노출되지 않아야 한다.
2. 테스트 캐릭터 누적 거리 99m/100m에서 경계를 확인한다. 수동 감상은 거리 기록을 바꾸지 않고 해당 이야기만 열어야 한다. 이미 열린 이야기는 거리 조회 실패 뒤에도 열려 있어야 한다.
3. 중간 종료·앱 재실행 후 이어 읽기, 마지막 페이지에 도착만 했을 때 미독 유지, ‘읽음으로 저장’ 후 읽음, ‘다시 읽기’ 첫 페이지 시작을 확인한다.
4. 나중에 읽기·뒤로 가기로 목록 위치 복귀, 화면 회전·재생성 후 캐릭터/페이지/스크롤 유지, 바로 달리기의 선택 캐릭터 전달을 확인한다.
5. 작은 화면·200% 글자·가로/세로에서 본문 스크롤, 고정 하단 버튼 접근, 겹침·잘림과 TalkBack 탐색을 확인한다. 이 레이아웃과 접근성 항목은 현재 정적 코드 검토만 수행했다.
6. 서로 다른 테스트 계정과 guest의 읽음·열림·책갈피 분리, 앱 재시작 후 유지, 조회 중 계정 변경과 늦은 콜백, 저장 실패 시 안내를 실제 환경에서 확인한다. 실제 Firebase 계정 전환·Firestore 장애는 이번 A 검토에서 실행하지 않았다.

### 공용 거리 저장소에 전달할 문제

- 코드에서 확인한 조건: LocalProgressStore.loadAll이 `progress_guest`의 `book`을 getString으로 읽는 구간은 예외 처리 밖이다. 테스트 저장소에서 book의 타입이 문자열이 아니면 ClassCastException이 나며, Result.failure 콜백 대신 호출 지점으로 예외가 전달될 수 있다. 실제 기기 재현은 수행하지 않았다.
- B 재현 절차: 별도 테스트 앱 데이터에서 book을 정수 타입으로 준비한 뒤 도감 진입 또는 loadAll 호출을 확인한다. 실제 사용자 기록을 손상시켜 시험하지 않는다. 유효한 JSON 문자열 내부의 손상은 ProgressBook.fromJson이 처리하지만 SharedPreferences 값의 타입 오류는 그 전에 발생한다.
- A는 도감 호출 경계에서만 예외를 받아 안내한다. 공용 저장소의 실패 콜백 보장, 손상 기록 처리 정책 및 다른 화면의 동작은 B가 결정·수정한다. 이 인계는 공용 코드 변경이나 기존 기록 초기화를 허용하는 지시가 아니다.
