# 짧은 캐릭터 대사 연결 기준

2026-11-10 / A팀 콘텐츠 납품 / content_ready_for_review / integrated=false.

원고는 SHORT_LINES.md, 연결용 데이터는 short-lines.json이다. 6명 × 8상황 × 독립 대안 3개 = 144개. 이번 작업은 대사와 노출 기준 작성이며 앱 화면·게임 엔진·공동 저장 스키마는 수정하지 않았다. 후속 이야기 제작, 음악 검수, 기존 도감 검수와 Git 업로드는 별도 작업이다.

## 상황과 정확한 트리거

| event | 노출 시점 | 제외 조건·우선순위 |
| --- | --- | --- |
| select | 사용자가 친구 선택 화면에서 캐릭터를 확정했을 때, 선택 카드 안 | 초기 렌더·회전·자동 복원 때 새 대사 추첨 금지. 빠른 탭 연타는 마지막 선택만 반영 |
| start | 새 판을 시작하는 버튼을 누른 뒤 기존 출발 준비 영역이 있을 때 | 읽으라고 출발을 지연시키지 않는다. 준비 영역이 없으면 생략. 재도전이면 retry만 사용 |
| stumble | 실패 결과 화면이 완전히 열린 뒤 | 충돌 순간·달리는 중 노출 금지. 판이 계속되는 가벼운 접촉에는 사용하지 않음 |
| retry | 사용자가 실패 결과에서 재도전 버튼을 직접 눌렀을 때 | 자동 재도전 금지. start와 중복 금지. 읽기 대기 없이 게임 시작; 준비 영역이 없으면 생략 |
| clear | 실제 cleared=true인 결과 화면 | 최고 기록·일시 정지·임의 종료는 완주가 아님. stumble와 상호 배타적 |
| home | 사용자가 ‘귀가’를 명시적으로 선택한 별도 귀가 화면 | 기존 ‘친구 선택으로’ 버튼이나 앱 백그라운드 이동에 붙이지 않음. 귀가 동선 미구현이면 예약 콘텐츠로 남김 |
| story_unread | ready이며 열린 미독 이야기의 상세 선택 영역 | 잠김·outline 카드에는 사용하지 않는다. 본문 페이지마다 반복하지 않음 |
| story_reread | 읽은 ready 이야기의 ‘다시 읽기’를 직접 선택했을 때 | 본문 첫 화면의 부가 문구로 1회, 이후 페이지에는 없음. 원문과 화자를 혼동하지 않게 영역 분리 |

선택 카드와 결과 화면 대사는 화면을 떠날 때까지 고정하며 자동 순환하지 않는다. 독서 시작 대사는 해당 진입에서 1회만 표시한다. 출발·재도전은 현재 진행 시간을 늘리지 않는 조건에서만 표시하고 새 강제 카운트다운을 만들지 않는다. 이번 콘텐츠를 위해 귀가 화면이나 보상 시스템을 새로 만들 필요는 없다.

## 선택·중복·빈도

1. 캐릭터 ID와 실제 event로 후보 3개를 고른다. 세 문장은 연속 대사가 아니다.
2. 캐릭터×event별로 3개를 섞은 큐를 사용하면 모두 한 번씩 나온 뒤 다시 섞을 수 있다. 새 큐 첫 항목이 직전 대사와 같으면 다른 항목과 바꾼다. 세션 메모리로 충분하며 서버 저장은 불필요하다.
3. 화면 회전·재구성에는 현재 선택 ID를 유지한다. 같은 결과의 재렌더링이나 거리 저장 콜백으로 대사를 추가 추첨하지 않는다. 결과의 runId와 event를 같은 표시의 기준으로 사용한다.
4. 첫 출발은 start, 재도전은 retry 중 하나만 사용한다. 실패 결과는 stumble, 성공 결과는 clear 중 하나만 사용한다. 이전 화면의 대사를 다음 화면으로 대기열 전달하지 않는다.
5. 빠른 캐릭터 전환은 300ms 안정화 후 마지막 카드의 대사 하나만 표시하는 것을 권장한다. 접근성 자동 낭독 연타도 방지한다.
6. 데이터나 후보가 없으면 말풍선만 생략한다. 게임·선택·독서는 정상 진행한다.

## 읽기와 조작

- 문자 수 제한은 48 Unicode 코드포인트, 현재 최대 25자다. 최대 2줄은 일반 글자 크기의 목표이며 큰 글자 설정에서는 높이를 늘리거나 스크롤을 허용한다. 강제 말줄임으로 대사를 자르지 않는다.
- 플레이어 입력 영역, 거리·점수·일시정지, 주요 버튼을 가리지 않는다. 전용 공간을 확보하지 못하면 장식 대사를 생략한다.
- 별도의 ‘대사 확인’ 버튼, 다음 대사 클릭, 보상 조건, 읽기 타이머를 만들지 않는다. 대사가 다 보이기 전에 출발·재도전·친구 선택·독서를 진행할 수 있다.
- 타자기 효과·자동 넘김·진동·음성은 기본 적용하지 않는다. 기존 시스템 안내와 오류는 장식 대사보다 우선한다. 중요한 오류를 말풍선으로 대체하지 않는다.
- 화자 이름을 텍스트로 제공하며 색만으로 구별하지 않는다. TalkBack 초점을 강제로 빼앗지 않고 사용자가 탐색할 수 있게 한다. 달리는 동안 대사를 자동 낭독하지 않는다.
- 이번 말풍선은 텍스트 표현이다. 몸짓·소품 애니메이션이 구현됐다는 약속이 아니며 연필, 마이크, 종이배 등을 게임 아이템으로 지급하지 않는다.

## 데이터 제안

독립적인 인계 데이터이며 아직 앱 assets나 공통 모델 계약에 편입하지 않았다. 개발 담당이 연결할 때 경로와 파서를 결정하고 DATA_CONTRACT.md 및 검증기에 반영한다.

- 최상위: schemaVersion=1, status=content_ready_for_review, integrated=false, maxTextCodePoints=48, events, lines.
- lines 항목: id, characterId, event, text, requiresReadStoryIds.
- ID: `<characterId>_<event>_<01~03>`. 공개 ID는 mint/cheese/popo/lumi/nunu/piko 유지. 문구를 다듬을 때 ID를 재사용하고 다른 상황으로 옮기면 새 ID를 발급한다.
- requiresReadStoryIds는 현재 전부 빈 배열이다. 144개 모두 첫 에피소드 결말·후속 개요의 사건을 몰라도 이해되며 읽음 조건을 요구하지 않는다. story_unread/story_reread의 대상 상태 판단은 별도다.
- status는 작성·검수용 상태로, 사용자 최종 문안 승인이나 앱 연결 완료를 뜻하지 않는다.

## 캐릭터·반복 검수

원고 말미에 라일·치즈, 포포·루미, 누누·피코의 쌍별 검토를 기록했다. 캐릭터 데이터의 말투·습관과 첫 에피소드 대사를 대조했다. 루미는 실패를 무조건 공연이었다고 부정하지 않고 쉬겠다고 말하며, 치즈는 새침함으로 플레이어를 탓하지 않는다. 누누는 죽음·소멸·접속 부재에 대한 죄책감을 유도하지 않는다. 피코의 빠른 설명은 재도전 압박 대신 준비 여부를 묻는 표현으로 끝낸다.

점수·실제 날씨·정확한 풍경·도착 장소·친구 NPC의 동행을 조건 없이 사실로 말하지 않는다. 캐릭터의 소품과 귀가 계획은 기존 생활 설정으로 사용한다. 포포가 소리를 떠올리는 말은 실제 오디오 재생 성공 여부와 연결하지 않는다.

기계 검사: 144개 ID 유일성, 텍스트 중복 0, 6명×8상황×3개, 48자 이하, 유효 캐릭터·event·읽음 조건 형식, Markdown/JSON 대조. 실제 화면 줄바꿈·낭독·타이밍 검수는 앱 연결 후 개발 담당이 수행한다. 이번 납품에서는 Android 코드 변경이나 빌드를 수행하지 않는다.

## 개발 담당 전달 범위

`docs/dialogue/SHORT_LINES.md`, `short-lines.json`, `HANDOFF.md` 및 PROJECT_STATE.md의 이번 기록만 대상이다. 기존 이야기·음원·다른 팀원 변경을 함께 stage하지 않는다. 앱 연결 시 우선 선택 카드와 결과 화면부터 적용하고, 준비/귀가 영역이 없는 이벤트는 생략 상태를 보고한다. 콘텐츠 작성 단계에서는 Git stage·commit·push하지 않았으며, 별도 게시 검수에서도 앱 미연결 상태를 유지한다.
