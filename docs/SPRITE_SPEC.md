# 캐릭터 스프라이트 규격 (B 확정, 2026-11-10)

ART_DIRECTION.md의 "64×64 셀 후보"를 이 문서로 확정한다. 근거: 받은 치즈·라일 시안의 몸이 약 32×32 도트이고, 러너 엔진 충돌 폭이 30이다. 48×48 칸이면 귀·꼬리·소품 여백이 남고, 1도트 = 게임 1단위로 바로 맞는다.

## 1. 프레임 크기
- **한 프레임 = 48 × 48 픽셀**, 실제 픽셀 그대로(1배) 내보낸다. 확대한 그림(예: 480×480)을 넣지 않는다. 게임이 정수 배로 키운다(1080p 가로 화면에서 3배 = 144px).
- 몸통·머리 높이는 **30~34도트**로 6명이 비슷하게 맞춘다. 누구도 더 커 보이지 않게 한다(물리 성능이 같다는 약속을 그림에서도 지킨다).
- 모두 **오른쪽을 본다**(달리는 방향).

## 2. 발 기준선과 충돌 영역
```
x: 0          9                         38        47
   +----------+-------------------------+----------+  y=0
   |  여백     |                         |   여백    |
   |  (꼬리,   |   몸통·머리·발은         | (주둥이,  |
   |   망토)   |   이 30도트 폭 안에       |  소품)    |
   |          |                         |          |
   +----------+-------------------------+----------+  y=45  ← 발바닥 마지막 줄
   |               (비워 둠: 착지 먼지용)              |  y=46~47
   +-------------------------------------------------+
```
- **발바닥 맨 아래 줄 = y 45** (0부터 셈). 46~47줄은 비운다. 서 있는 모든 프레임에서 같다.
- **몸통 가운데 = x 24.** 몸통과 발은 x 9~38(30도트) 안에 둔다. 이 영역이 실제 충돌 판정이다.
- 귀·꼬리·스카프·망토·소품은 영역 밖으로 나가도 된다. 충돌에 쓰이지 않는다.
- **점프 프레임도 발 위치를 위로 올리지 않는다.** 높이는 게임이 움직인다. 그림 속에서 몸을 띄우면 점프가 두 번 적용된다.
- 얼굴(눈) 위치는 같은 동작 안에서 ±1도트 안으로 유지한다. 넘으면 재생할 때 떨려 보인다.

## 3. 동작별 프레임 수
| 우선 | 동작 | 파일 동작명 | 프레임 | 재생 | 쓰이는 곳 |
| --- | --- | --- | --- | --- | --- |
| 필수 | 대기 | idle | 2 | 0.5초씩 반복 | 선택·프로필·출발 전 |
| 필수 | 달리기 | run | 4 | 달린 거리에 맞춰 반복(처음 약 초당 10장) | 달리는 중 |
| 필수 | 점프 | jump | 2 | 0 = 올라갈 때, 1 = 내려올 때 | 공중 |
| 필수 | 실패 | fail | 1 | 결과 화면 전 0.9초 | 부딪힌 순간 |
| 선택 | 착지 | land | 1 | 0.08초 | 땅에 닿은 직후 |
| 선택 | 선택 인사 | greet | 2 | 0.25초씩 1회 | 친구 고를 때 |
| 선택 | 귀가 | home | 2 | 0.5초씩 반복 | 결과 화면 |

- 캐릭터당 필수 9장, 6명 54장. 선택 동작까지 하면 14장, 84장.
- 실패는 다치거나 우는 모습이 아니라 ART_DIRECTION의 "머쓱", "갸웃" 같은 가벼운 감정으로 표현한다.

## 4. 파일 이름과 저장 경로
| 종류 | 경로와 이름 | 예 |
| --- | --- | --- |
| 게임 프레임 | `app/src/main/res/drawable-nodpi/sprite_<id>_<동작>_<번호>.png` | `sprite_cheese_run_0.png` |
| 콘셉트 원본(앱에 안 들어감) | `docs/art/concepts/<id>_concept.png` | `docs/art/concepts/mint_concept.png` |
| 편집 원본(선택) | `docs/art/source/<id>.<확장자>` | `docs/art/source/cheese.piskel` |

- `<id>`는 표시 이름이 아니라 데이터 ID다: `mint`(라일), `cheese`, `popo`, `lumi`, `nunu`, `piko`.
- 번호는 0부터 센다: `run_0`~`run_3`.
- 소문자·숫자·밑줄만 쓴다(Android 리소스 규칙). 한글, 공백, 대문자, 하이픈을 쓰면 빌드가 실패한다.
- `drawable-nodpi`는 기기 화면 밀도에 따라 자동으로 늘리지 않는 폴더다. 도트가 흐려지지 않는다.

## 5. PNG 규칙
- 투명 배경 RGBA PNG. 흰 배경을 남기지 않는다.
- 안티앨리어싱(가장자리 흐림)과 부드러운 그림자를 쓰지 않는다. 모든 픽셀은 완전 불투명 또는 완전 투명이다. 예외: 누누의 반투명 몸은 한 가지 투명도만 쓴다.
- 캐릭터당 16색 이하(윤곽 포함). 윤곽은 6명 공통 짙은 갈색 한 가지.
- 1도트보다 가는 선(반 칸 눈썹, 가는 수염)을 쓰지 않는다. 생성 이미지에서 이런 선은 1도트로 다시 찍는다.

## 6. 인수와 검사
- 프레임을 넣으면 `node scripts/validate-content.cjs`가 이름·크기·형식을 검사하고, 캐릭터별 필수 프레임이 몇 장 있는지 알려준다.
- 필수 9장이 모두 있는 캐릭터만 게임에서 스프라이트로 바꾸고, 나머지는 지금의 임시 그림을 쓴다. 그래서 2명씩 나눠 넣어도 6명 선택은 유지된다.
- 한 캐릭터의 필수 9장이 다 들어가면 `characters.json`의 `spritePath`를 `"sprite_<id>"`(파일 이름 앞부분)로, `assetStatus`를 `"sprite_ready"`로 바꾼다. 이때부터 검사기가 9장이 모두 있는지 강제한다.
- 연결(4단계 B): 게임은 발 기준선(y 45)을 땅에 맞추고 x 24를 충돌 영역 가운데에 맞춰 정수 배로 그린다(필터 없이 가장 가까운 픽셀).
