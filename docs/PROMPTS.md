# 단계별 복사용 프롬프트

공통 지침과 본인의 해당 단계 프롬프트를 함께 사용한다.

## 공통 지침

우리는 학교 과제로 Android Studio에서 실행·시연·제출할 2D 픽셀 러너 앱 Tiny Runners를 2명이 만들고 있다. 나는 [A: ChatGPT 담당 / B: Claude 담당]이다. 이번에 지정한 단계와 내 담당 파일만 작업하라.
최종 목표와 첫 시연의 캐릭터 선택 수는 모두 6명이다. 캐릭터 수를 임의로 줄이지 마라. 초기에는 6명 모두 임시 소재로 플레이할 수 있게 만들고, 배경·연출·음악·서사는 단계적으로 완성한다.
과제의 언어와 UI 방식은 아직 제공되지 않았다. 본 계획은 Kotlin + XML 화면 + Custom View/Canvas 게임 화면을 임시 기준으로 삼는다. 과제 안내가 제공되면 그것을 우선하라. 실제 프로젝트의 SDK·Gradle·플러그인 버전을 확인하고 서로 맞는 버전을 사용하라. 이 문서의 예정 기능을 구현 완료로 간주하지 마라.
A는 기획·캐릭터 콘텐츠·이미지 제작과 소개/선택/도감 화면을 맡는다. B는 프로젝트 설정·게임 로직·오디오·저장·통합을 맡는다. 공통 데이터 계약과 파일 소유권을 먼저 확인한다. 담당 밖 파일은 변경 필요성을 기록하고 상대 작업을 덮어쓰지 않는다.
6명은 mint, cheese, popo, lumi, nunu, piko이다. 각자 외형·고향·성격·이야기·테마 음악이 다르지만 속도·점프·기본 충돌 판정은 같다. 능력 차이 없이 좋아하는 친구를 고르게 한다.
귀엽고 따뜻한 판타지로 다양한 감정을 표현한다. 입시·취업·빚·질환 같은 현실 소재를 직접 넣지 않는다. 쓸모를 증명해야 사랑받는 결말, 과잉 비극, 매번 같은 위로 대사, 미접속 죄책감, 출석 실패 벌칙을 넣지 않는다.
기존 4종의 승인된 픽셀 디자인을 유지한다. 생성 이미지를 완벽한 스프라이트나 무한 반복 배경으로 가정하지 않는다. 실제 음원이 없으면 음악이 완성되었다고 말하지 않는다. 205편 연구는 원문·실질 줄거리 검토이며 모두 완독하거나 영화를 전편 시청한 것이 아니다.
매 단계 결과는 실제 파일, 실행 방법, 검증 결과, 남은 문제로 제시한다. 실행하지 않은 테스트는 통과로 표시하지 않는다. PROJECT_STATE.md를 갱신하고 이번 단계가 끝나면 멈춘다. 다음 단계는 사용자가 요청할 때 진행한다.

## 1단계 A ChatGPT

공통 지침을 따라 A 역할을 수행해줘. 기존 205편 이야기 조사와 유사 게임 비교를 활용해 목표·필수 기능·화면 흐름·6명 목록을 기획서로 정리해줘. 첫 시연부터 6명 선택과 6명 플레이가 가능하다는 조건을 명시해줘. 소개→캐릭터 선택→게임→결과→도감/재시작 흐름을 설계해줘. 과제 안내에서 아직 모르는 언어·화면 방식·마감·제출물은 미확정 항목으로 적고 임의로 교수님 요구라고 쓰지 마. B와 합의할 characterId, 이름, 성격, home, portraitPath, spritePath, backgroundId, musicId, storyIds 필드를 제안해줘. 코드는 아직 작성하지 마.

## 1단계 B Claude

공통 지침을 따라 B 역할을 수행해줘. A의 기획서를 읽고 Android Studio 프로젝트 구성과 공동 데이터 계약을 제안해줘. Kotlin+XML+Custom View/Canvas는 과제 조건이 없을 때의 임시안이다. CharacterDefinition, StoryEpisode, RunResult, Progress 구조와 화면 간 characterId 전달 규칙을 문서화해줘. 스프라이트 크기·프레임 이름·발 기준선·배경 크기·음원 형식·경로 규칙을 정해 A에게 전달해줘. 실제 프로젝트 버전과 실행 환경을 확인하고, 아직 확인하지 못한 것은 따로 적어줘.

## 2단계 A ChatGPT

확정한 데이터 계약을 사용해 캐릭터 6명의 이름·종족·사는 곳·성격·생활 습관·애착 소품·달리는 이유·말투를 작성해줘. 라일·치즈·포포·루미·누누·피코 6명으로 확정하고 따뜻한 픽셀 디자인을 유지해줘. 6명이 모두 외로움이나 열등감을 해결하는 같은 이야기가 되지 않게 감정과 갈등을 나눠줘. characters.json과 각자의 짧은 소개를 작성하고 중복 ID·없는 참조를 검사해줘. 배경과 음악은 실제 제작 전이므로 placeholder 또는 planned 상태로 명확히 구분해줘.

## 2단계 B Claude

합의한 구조로 Android Studio 프로젝트 골격을 만들어줘. 앱 시작, 소개, 선택, 게임, 결과, 도감 화면이 이어지게 하되 A가 담당할 소개/선택/도감은 최소 연결용 틀만 준비해줘. CharacterRepository가 6개 데이터를 읽고 잘못된 ID를 안전하게 처리하게 해줘. 6명의 임시 그림을 구별할 수 있게 표시하고 선택한 ID가 게임 화면까지 전달되는지 확인해줘. 빌드 성공과 에뮬레이터 또는 실제 기기 실행을 확인하고 프로젝트 실행 방법을 기록해줘.

## 3단계 A ChatGPT

A 소유 화면을 구현해줘. 캐릭터 선택 화면에 6명 전원을 표시하고 이름·짧은 성격·사는 곳·선택 표시·시작 버튼을 제공해줘. 카드 선택이 단순 장식이 아니라 해당 characterId를 실제 게임에 전달하게 해줘. 아직 실제 이미지가 없으면 임시 소재임을 표시해줘. 목록 아래 친구도 접근 가능해야 하고 작은 화면에서 글자와 버튼이 잘리지 않아야 해. 6명 선택을 순서대로 검증하고 B에게 연결 규격을 전달해줘.

## 3단계 B Claude

6개 캐릭터 데이터를 모두 사용할 수 있는 공통 러너 로직을 구현해줘. 자동 전진, 터치 점프, 중력, 장애물 생성, 충돌, 거리/점수, 재시작, 일시정지를 만들어줘. 캐릭터에 따라 물리 수치가 달라지지 않게 하고 렌더링과 게임 상태를 분리해줘. 프레임 시간 기준으로 이동시키고 장애물 간격을 실제 점프 가능 범위 안에서 생성해줘. 최소·최대 속도와 6개 선택 ID로 시작→점프→충돌→재시작을 확인해줘. 아직 완성 아트가 없어도 6명 모두 플레이가 가능해야 해.

## 4단계 A ChatGPT

확정한 6명 목록과 승인된 디자인 방향을 기준으로 캐릭터 6종의 실제 디자인을 만들어줘. 2명씩 작업하되 선택 가능 인원은 계속 6명으로 유지해줘. 같은 픽셀 크기·윤곽선·비율·팔레트 규칙을 적용하고 서로 다른 실루엣과 소품을 유지해줘. 각자 선택 인사, 대기, 달리기, 점프, 착지, 실패, 귀가 동작을 설계해줘. B와 합의한 프레임 규격으로 만들고 발 기준선·얼굴 일관성·잘린 귀와 꼬리를 검사해줘. 생성 결과가 규격을 못 맞추면 수정 필요로 표시해줘.

## 4단계 B Claude

A가 전달한 스프라이트를 게임에 적용해줘. 캐릭터별 애니메이션 상태 전환을 공통 구조로 만들고 프레임 규격을 자동 검사해줘. 얼굴/발 위치 떨림과 확대 시 흐려짐을 확인해줘. 스카프·꼬리·귀·안테나·날개 연출은 시각적으로 달라도 충돌 판정과 체공시간은 같게 유지해줘. 실패 연출을 본 뒤 재시작해도 이전 상태가 남지 않게 해줘. 소재가 없는 캐릭터는 명시적인 임시 그림으로 안전하게 동작해야 해.

## 5단계 A ChatGPT

캐릭터 설정집을 바탕으로 고향 배경을 6종 개별 생성해줘. 단순 색상 교체가 아니라 지형·건축·생활 소품·시간대를 구별해줘. 먼저 2종을 만들어 합의한 규격과 스타일을 확인한 뒤 같은 기준으로 나머지를 제작해줘. 캐릭터·UI·글자는 배경에 넣지 말고 달리는 영역을 비워줘. 하늘·먼 풍경·가까운 장식·바닥의 분리 계획을 제공해줘. 콘셉트 이미지와 실제 반복 스크롤용 소재를 구별하고 실제로 끊김 없이 반복되는지 검사해줘.

## 5단계 B Claude

고향 배경 6종을 backgroundId로 연결해줘. 원경·중경·근경을 서로 다른 속도로 움직이게 하고 캐릭터와 장애물보다 배경이 두드러지지 않게 해줘. 과도한 레이어나 파티클로 프레임이 떨어지지 않도록 확인해줘. 화면 비율이 달라도 바닥 기준선과 충돌 위치가 맞아야 해. 배경 반복 이음새·빈 틈·캐릭터 변경 시 이전 배경 잔상을 검사해줘.

## 6단계 A ChatGPT

캐릭터 6명 각각의 성격·고향·감정에 맞는 음악 제작 명세와 복사용 음악 프롬프트를 만들어줘. 악기·템포·멜로디 방향·감정·반복 길이를 구별해줘. 같은 곡의 속도나 악기만 바꿔 6곡이라고 하지 마. 목표는 곡당 60~90초 정도의 오리지널 기악 반복곡이다. 실제 사용할 수 있는 작곡·음악 생성 경로를 확인하고, 만들 수 없다면 프롬프트만 있는 상태와 실제 음원이 있는 상태를 구분해줘. 특정 아티스트나 곡 복제를 요청하지 말고 파일별 제작 출처·이용 조건을 기록해줘.

## 6단계 B Claude

musicId에 대응하는 실제 음원을 캐릭터별로 연결해줘. 음악과 짧은 효과음을 분리하고 음량·음소거·설정 저장을 구현해줘. 선택 변경, 시작, 일시정지, 재시작, 앱 백그라운드 이동과 복귀에서 중복 재생이 없도록 해줘. 오디오 포커스와 자원 해제를 처리하고 반복 구간 클릭음·음량 편차를 실제로 들어 확인해줘. 아직 음원이 없는 캐릭터는 무음 또는 명확한 임시곡으로 처리하고 정식 6곡 완료로 표시하지 마.

## 7단계 A ChatGPT

205편 조사에서 얻은 원리를 활용하되 기존 사건·대사·상징을 조합 복제하지 말고 6명 고유의 이야기를 작성해줘. 캐릭터마다 메인 배경 이야기와 첫 에피소드 1개를 완성하고 후속 에피소드 2개는 개요로 준비해줘. 본문은 2명씩 검토하며 감정과 결말의 반복을 줄여줘. stories.json과 도감 화면을 구현하고 읽은 이야기·다시 읽기·아직 열리지 않은 이야기를 구분해줘. 긴 글을 읽지 않아도 게임을 계속할 수 있어야 해.

## 7단계 B Claude

캐릭터별 누적 거리, 최고 기록, 본 이야기, 얻은 기억을 저장해줘. 실패한 달리기도 동행 기록에 반영하고 재시작이나 결과 화면 재진입으로 중복 누적되지 않게 해줘. 데이터 저장과 화면 표시를 분리하고 A의 도감에서 읽을 수 있는 인터페이스를 제공해줘. 해금 수치는 짧은 시연으로 검증 가능한 범위로 조정하되 테스트용 데이터와 실제 저장을 구분해줘. 미접속 페널티나 관계 감소는 넣지 말고 앱 종료·재실행과 손상된 데이터의 복구 경로를 확인해줘.

## 8단계 A ChatGPT

앱 안의 소개 화면을 완성해줘. 제목과 핵심 콘셉트, 6명의 친구, 각자의 고향·음악·이야기, 시작 버튼을 명확하게 배치해줘. 아직 구현 안 된 기능은 홍보 문구에서 완료처럼 쓰지 마. 학교 발표에 사용할 소개서도 문제/기획 의도→플레이 흐름→기능→차별화 방향→역할 분담→시연 순서로 정리해줘. 소개 화면과 실제 게임의 말투·디자인을 맞춰줘. 별도 웹사이트 제작은 이번 과제의 필수 작업으로 추가하지 마.

## 8단계 B Claude

소개→선택→게임 흐름과 처음 이용할 때의 3~4단계 안내를 연결해줘. 다음 버튼·건너뛰기·다시 보기·안내 완료 상태 저장을 제공해줘. 안내 화면을 누른 동작이 게임 점프로 전달되지 않게 해줘. Android 뒤로가기, 게임 중 나가기, 복귀 시 일시정지, 이야기 화면에서 게임으로 돌아오는 흐름을 확인해줘.

## 9단계 A ChatGPT

구현자의 설명만 믿지 말고 전체 변경 내용을 별도로 검수해줘. 6명 선택, 그림/배경/음악 매핑, 최대 속도 점프 가능성, 충돌 판정, 기록 중복 누적, 이야기 참조 오류를 확인하는 테스트와 검증 도구를 작성해줘. 직접 실행할 수 없는 Android 기기 항목은 팀원이 따라 할 재현 절차로 제공하고 미검증으로 남겨줘. 실제 화면에서 글자 잘림·흐릿한 픽셀·불필요한 효과·캐릭터 설정 모순을 찾아 수정 목록을 만들어줘.

## 9단계 B Claude
