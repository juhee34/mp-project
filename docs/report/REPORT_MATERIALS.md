## 1. 서비스 개요 (보고서 ①)

**한 줄 소개:** 여섯 친구의 고향을 함께 달리며, 달리는 사이사이 그 친구의 이야기를 RPG 대화창으로 듣는 Android 픽셀 러닝 게임.

**해결하려는 문제(우리가 세운 기획 과제):** 짧은 러닝 게임은 점수만 남고 함께 달린 캐릭터는 기억에 잘 남지 않는다. 또 캐릭터마다 성능이 달라 "센 캐릭터"만 고르게 되기 쉽다. → 성능은 똑같이 두고, 고향·성격·이야기로 친구를 고르게 했다. (사용자 조사로 검증한 사실이 아니라 우리가 세운 디자인 과제다.)

**타깃 사용자(제안):** 짧은 시간에 한 판씩 즐기는 캐주얼 게임 이용자, 귀여운 픽셀 캐릭터와 이야기를 좋아하는 이용자. [확인 필요: 연령대·근거는 기획 담당이 정리]

**핵심 차별점 (경쟁 앱 비교에 쓸 수 있는 우리 쪽 사실)**
- 여섯 친구 모두 처음부터 선택 가능, 점프·속도 등 물리 성능 동일(성능 차이 없는 선택).
- 친구마다 고향·성격·배경 그림·음악·이야기(소개 + 3편)가 다르다.
- 실제 날씨(외부 API)가 달리기 하늘과 길 난이도에 반영된다.
- 이야기 진행: 달리기 전 대화 → 달리는 중 짧은 말풍선 → 갈림길 선택 → 결말 대화.
- 현실의 입시·취업·빚·질환 소재와 출석 압박을 쓰지 않는다.

**경쟁 앱 후보** [확인 필요: 기획 담당이 스토어 정보로 직접 확인·출처 기재]
| 비교 후보 | 비교해 볼 점 |
|---|---|
| 쿠키런: 오븐브레이크 (데브시스터즈) | 캐릭터별 능력 차이, 수집·성장 중심 |
| 템플 런 계열 무한 러너 | 이야기 없이 기록 경쟁 |
| 이야기 중심 캐주얼 게임 | 대화·선택 위주, 조작 게임성 |

**화면 사이 데이터 전달 (Intent extra 예)**
- 선택 → 달리기: `characterId`, `storyId`(고른 편), 튜토리얼이면 `showGuide`
- 달리기 → 결과: `meters`, `score`, `cleared`, `runId`, 주운 아이템·보너스 코인, 그날 날씨(도시·하늘·기온·낮밤)
- 메뉴 → 세계 이야기: `firstTime`(처음이면 끝난 뒤 친구 선택으로)
- 이야기 모음 → 도감: `characterId`

**게임 규칙 요약:** 탭 = 점프, 공중에서 한 번 더 = 2단 점프. 장애물: 상자·탑·가시 막대(아래로 통과)·바닥 가시(발판). 25m마다 1코인. 날씨에 따라 길 난이도 5단계(맑은 낮 쉬움 ~ 폭풍 밤 가장 어려움). 눈 바위 장애물은 포포·누누 길에만.

## 3. 시스템 구조와 사용 기술 (보고서 ③)

**개발 환경:** Android Studio, Kotlin 2.0.21, Android Gradle Plugin 8.7.3, JDK 17, compileSdk/targetSdk 35, minSdk 26(Android 8.0). 화면은 코드로 만든 View + Canvas(게임·그림). [질의 대비: 수업 문법은 Java, 우리는 Kotlin — 같은 JVM·Android API를 쓴다는 점을 설명]

**BaaS: Firebase**
- Authentication: 이메일/비밀번호 회원가입·로그인, 게스트(익명) 로그인.
- Cloud Firestore(원격 저장) 구조
  - `users/{uid}/progress/{characterId}`: 친구별 누적 거리·최고 기록·횟수·본 이야기(readStoryIds)
  - `users/{uid}/runs/{runId}`: 판마다 거리·점수·특별 날씨 (같은 runId는 한 번만 저장되도록 트랜잭션)
  - `users/{uid}/shop/state`: 산 꾸미기·음악·장애물, 장착 상태, 충전·사용 코인
  - `users/{uid}/items/bag`: 가방 아이템
- 사용량 감각(예산 계산용): 한 판 끝날 때 트랜잭션 1번(문서 2개 읽기 + 2개 쓰기), 화면 열 때 progress 6문서 읽기, 상점 열 때 수 문서 읽기. 문서는 모두 작다(수백 바이트 수준).

**로컬 저장(SharedPreferences):** 설정(소리·날씨 도시), 날씨 캐시(최근 3시간), 세계 이야기 본 여부(계정별), 도감 책갈피, 게스트 진행 등.

**외부 API: 날씨**
- 1순위 Open-Meteo `api.open-meteo.com/v1/forecast` (현재 날씨 코드·기온·낮밤, 키 없음, CC BY 4.0, **비상업적 이용 무료**)
- 2순위(백업) MET Norway `api.met.no/weatherapi/locationforecast/2.0` (노르웨이 기상청, 키 없음, CC BY 4.0, 앱 이름을 User-Agent로 밝혀야 함)
- 둘 다 실패하면 3시간 안에 받은 마지막 날씨 사용. 요청 제한시간 4~5초. 도시 7곳(서울·인천·대전·대구·광주·부산·제주) 고정 목록이라 위치 권한 없음.
- 쓰임: 달리기 하늘(비·눈·안개·폭풍·밤), 길 난이도, 특별 날씨 엽서, 설정 화면 "서울 · 흐림 10°C".

**콘텐츠 데이터(앱 안 JSON):** 캐릭터 6명, 달리기 이야기 24편(친구별 소개+3편, 4막 구성·갈림길·결말 3종), 도감 본문, 짧은 상황 대사, 엽서 12장.

**검증:** 단위 테스트 130개, Android Lint, 콘텐츠 검사 스크립트 통과. 에뮬레이터(2400×1080)에서 주요 화면 확인. [실제 휴대폰 시험은 아직]

## 5. 시연 준비 메모 (발표용)

- 시연 흐름(약 3분): 오프닝 → 로그인 → (처음 계정이면) 세계 이야기 → 친구 선택 → 이야기책에서 편 고르기 → 달리기(대화·점프·갈림길) → 결과 → 상점·설정 날씨.
- 에뮬레이터 시간대가 GMT면 저녁에도 낮 배경이 나온다 → 시연 전 한국 시간으로 맞추기.
- 발표장 와이파이에서 날씨가 뜨는지 미리 확인(Open-Meteo가 안 되면 MET Norway로 받아 옴).
- 세계 이야기는 계정당 처음 한 번 자동으로 열린다 → 새 계정을 쓰거나 이야기 모음 첫 책에서 열기.
- Firebase 설정 파일(google-services.json)은 저장소에 없다(보안). 코드만 받은 사람은 로그인·저장을 쓰려면 이 파일이 필요하다 → 제출 방법은 팀이 결정.
